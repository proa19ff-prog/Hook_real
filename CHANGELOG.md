# Changelog

Все заметные изменения проекта документируются в этом файле.
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## [0.6.2] — 2026-11-12

### Added
- Серверный RAM-кеш: популярные треки заранее лежат в памяти процесса, а не
  только на диске. Воспроизведение идёт из памяти (`_serve_ram`) с поддержкой
  Range, поэтому перемотка отвечает за 2 мс, а старт — за 9 мс вместо
  похода на диск. Объём задаётся `HOOK_RAM_CACHE_MB` (по умолчанию 320 МиБ,
  не больше 24 МиБ на файл); кеш прогревается при старте по числу
  прослушиваний и пополняется при первом проигрывании.
- Новые маршруты резолвера: `GET /popular?limit=` (треки, которые уже
  разрешены и обычно лежат в RAM), `GET /warm?ids=` (до 12 ID — «прогреть
  сейчас»), `GET /stats` (размер кеша, треки в памяти, попадания).
- Поиск и разрешение на сервере кешируются в процессе (`OrderedDict`, 1024
  записи) с single-flight: десять одинаковых запросов подряд выполняют одну
  работу, а не десять. Клиент переиспользует один `requests.Session` вместо
  нового TLS-рукопожатия на каждый трек.
- Приложение греет следующие треки заранее (`/warm`) и резолвит поток
  параллельно: прямой YouTube и сервер стартуют одновременно, побеждает тот,
  кто ответил первым. Раньше сервер вызывался только после 4-секундного
  таймаута прямого запроса.
- Настройки воспроизведения: вибрация, предзагрузка следующих треков и
  «меньше анимации» (последнее принудительно включает `disableAnimations`
  для всего дерева).
- Понятное сообщение для треков 18+: вместо общего «источник не смог
  воспроизвести» приложение говорит, что трек с возрастным ограничением и
  серверу нужны куки YouTube от аккаунта, который вошёл в систему. Показание
  переводится на все 20 локалей.

### Fixed
- **Куки «отлетали» с сервера.** `yt-dlp` при закрытии каждой загрузки писал
  свой cookie-jar обратно в файл (`save_cookies() → cookiejar.save()`), а
  `load_cookies` читал файл с параметрами по умолчанию. В итоге каждый
  resolve, поиск и скачивание перезаписывали главный `cookies.txt`. Теперь
  каждый вызов получает одноразовую копию во временном файле, а главный jar
  меняется только при загрузке — значение ротационных токенов больше не
  затирается параллельными потоками (32 потока waitress писали свои, уже
  устаревшие копии). Временные копии удаляются сразу; оставшиеся от падений
  подметает уборщик раз в 6 часов.
- Здоровье кук больше не врёт. `/cookies/status` и `/cookies/upload` теперь
  возвращают `signed_in`, а новый `/cookies/verify` задаёт YouTube живой
  вопрос `LOGGED_IN` и отдаёт `age_restricted_ready`. Раньше файл с одними
  гостевыми куками считался здоровым, и 18+ молча не работали.
- Загрузка кук проверяет экспорт до замены: мусор вместо Netscape-файла,
  файл без youtube-кук или полностью истёкший экспорт отклоняются, а прежний
  jar остаётся на месте (новый сохраняется как `cookies.txt.bak`). Ответ
  прямо говорит, является ли экспорт входом в аккаунт.
- Возрастной отказ больше не повторяет дорогую работу: вердикт «18+ без кук»
  запоминается на 30 минут и сбрасывается при удачном разрешении или загрузке
  нового jar. Повторные нажатия отвечают за 1.7 мс вместо 1.5 с.
- Сервер отвечает `403 {"error":"age_restricted"}` и `403 cookies_stale`
  вместо общего `502 unavailable`, поэтому приложение может объяснить
  причину, а не показать «недоступно».
- В настройках появился статус кук с кнопкой «Проверить»: он показывает,
  подключён ли аккаунт и доступны ли треки 18+, и запускает живую проверку
  только по нажатию — `/cookies/verify` ходит в YouTube и не должен
  срабатывать при каждом открытии экрана.

## [0.6.1] — 2026-11-11

### Added
- Тема под Windows: пресеты «Windows 11» (тёмный) и «Windows 11 Light» —
  фон Mica, карточки `#2C2C2C`, акцент `#60CDFF`, радиус 8 и Segoe UI вместо
  скошенных углов и кастомного шрифта. Обе темы лежат в списке тем рядом с
  прежними, тема по умолчанию не изменилась.
- Управление системной громкостью Windows: слайдер прямо в нижней панели
  плеера, полный микшер по клику (системный уровень и отдельная громкость
  Hook с пояснениями), шаг 2 % и синхронизация с клавишами ноутбука и
  системным микшером через слушатель аудиоэндпоинта.
- Панель плеера для широкого окна: обложка и трек слева, транспорт и
  перемотка по центру, громкость, микшер, лирика и полноэкранный режим
  справа. На узком окне панель сама убирает таймкоды и инлайн-слайдер,
  прежде чем сжать транспорт.
- Боковой рейл навигации вместо нижнего таба на десктопе: «Главная»,
  «Поиск», «Медиатека» плюс быстрые переходы в статистику, темы и настройки.
- Горячие клавиши: `Space` — играть/пауза, `←` `→` — перемотка на 10 секунд,
  `Ctrl + ←` `Ctrl + →` — предыдущий/следующий трек, `Ctrl + ↑` `Ctrl + ↓` —
  громкость, `M` — без звука. Список с клавишами-«кнопками» появился в
  настройках, потому что из интерфейса эти биндинги иначе не видны.
- Дизайн-токены (`HookSpace`, `HookRadius`, `HookType`, `HookMotion`,
  `HookBreakpoints`) и единый адаптер иконок: Material `Icons.*` и сырые
  MingCute id больше не встречаются в экранах.
- Скелетоны загрузки для библиотеки и поиска, прокручиваемая шапка поиска
  с блюром, панель кэша с реальным путём и кнопкой «Скопировать», тактильный
  отклик на навигацию, транспорт, перемотку и избранное.
- Статистика переписана: недельная диаграмма, топ исполнителей и карточки
  сводки на `MaterialLocalizations`, без захардкоженных подписей.

### Fixed
- Горячие клавиши больше не съедают ввод: пробел, стрелки и `M` срабатывают
  только вне текстовых полей — раньше поиск и диалоги теряли символы.
- Громкость Hook переживает перезапуск: значение восстанавливается при
  следующем запуске и сразу применяется к плееру, а не только к эквалайзеру.
- Слайдер системной громкости больше не «залипает» в mute: если Windows
  сообщает о выключенном звуке (клавиши ноутбука, системный микшер),
  движение слайдера включает звук обратно, а не меняет громкость вслепую.
- Панель плеера переполнялась при минимальной десктопной ширине окна:
  таймкоды и инлайн-слайдер теперь уступают место транспорту.
- Список горячих клавиш в настройках и раздел обновлений больше не
  переполняются на узком экране с крупным системным шрифтом: клавиши
  переезжают на отдельную строку, длинные подписи ужимаются.
- Подсказка в микшере обещала `↑ ↓`, хотя громкость меняется по `Ctrl + ↑ ↓` —
  исправлено во всех 20 языках.

### Changed
- Единые отступы, радиусы и кегли по всему приложению вместо литералов;
  ширина читаемых экранов сведена к одному брейкпоинту.
- Микшер громкости открывается диалогом на десктопе и шторкой на телефоне —
  один и тот же контент в привычном для платформы контейнере.

## [0.3.0] — 2026-11-08

### Added
- OTA-обновления: раздел «Обновления» в настройках сам проверяет GitHub
  Releases (раз в 6 часов и по кнопке), показывает новую версию с
  описанием, скачивает APK под архитектуру устройства с прогрессом и
  открывает системный установщик. Резолвер-эндпоинты образуют пул с
  авторотацией: при исчерпании квоты воркера (429) или сетевом сбое
  запросы автоматически уходят на следующий адрес.
- Импорт плейлистов по ссылке с YouTube Music, YouTube и Deezer: сервер
  читает публичный плейлист одним извлечением (yt-dlp / публичный API
  Deezer) и отдаёт треки списком. YouTube-треки импортируются как готовые
  записи с точными id и играют сразу; треки Deezer сопоставляются с
  каталогом, как вставленный список. CSV/TXT и Spotify-ссылки работали
  и раньше. Личные плейлисты («Мне нравится») платформы по ссылке не
  отдают — только публичные.
- Лирика сама догоняет версии с интро: если играющая запись длиннее той,
  под которую размечен текст (YouTube-риаплоады с вступлением), караоке
  сдвигает тайминги на разницу — до 40 секунд, один раз за трек и никогда
  поверх ручной подстройки. Ручной офсет теперь в пределах ±45 с.
- Кнопка скачивания трека: в меню трека и в шапке полноэкранного плеера — с
  живым прогрессом, состоянием «Скачано» и битрейтом выбранного потока.
  Скачанные треки помечаются значком в списках и продолжают играть офлайн.
- Указание битрейта потока: резолвинг теперь знает качество выбранного аудио
  (YouTube — максимальный битрейт среди аудиодорожек, SoundCloud —
  progressive MP3 128 kbps) и показывает его при скачивании.

### Fixed
- Кнопка «Скачать» теперь доигрывает до файла: перебирает источники по
  надёжности — прямая ссылка источника → серверный прокси того же трека →
  матчинг воспроизведения → серверная упаковка yt-dlp. Прямые GET YouTube
  с российских сетей отбиваются 403 — сервер качает вместо телефона.
- Скачивание SoundCloud: файл запрашивается тем же Range-запросом, что и
  стрим (часть CDN отбивала обычный GET), ответ 206 принимается только с
  content-range от нуля; для сохранения берётся только цельный
  progressive-файл — HLS-плейлист стримится, но файлом быть не может.
- Светлые (бежевые) темы: тёмные `surface`/`surfaceGlass`, попавшие в палитру
  темы, больше не превращают поле поиска, диалоги и меню в чёрные плашки —
  поверхности принудительно приводятся к семейству яркости фона. Рамки,
  неразличимые на фоне, восстанавливаются.
- Контраст текста на светлом акценте: чипы языков и кнопки с заливкой
  primary/accent выбирают тёмные чернила вместо захардкоженного белого
  (`HookColors.onPrimary` / `onAccent`).

### Fixed
- Обложки в плейлистах снова загружаются: сохранённые http-ссылки (например,
  обложки NetEase) переводятся на https — приложение не ходит по открытому
  трафику, — а устаревшие подписанные обложки YouTube заменяются каноническими
  без подписи. То же применяется к обложке в уведомлении и палитре темы.
- Тексты: ответ `/get` LRCLIB теперь проверяется на совпадение исполнителя —
  раньше под эту песню мог подставиться другой трек с тем же названием.
  Запись чужого исполнителя с тем же названием и близкой длительностью больше
  не считается совпадением: без текста лучше, чем с чужим.

### Added
- Страница артиста: имя исполнителя в любом треке нажимается и открывает все
  его найденные записи — каноничная дискография каталога плюс совпадения из
  остальных источников, с кнопкой «Волна от артиста».
- История поисковых запросов: недавние запросы сохраняются на устройстве,
  показываются чипами на пустом экране поиска, удаляются по одному или всё
  сразу.
- Персональные рекомендации: устройство ведёт счётчики прослушиваний, «Волна»
  подмешивает треки артистов из твоей ротации в каждый пакет, а при первом
  запуске домашняя волна сама предлагает стартовый трек. Диагностика пополнена
  стадиями wave.batch / wave.batch.failed.
- Обложка плейлиста — коллаж 2×2 из обложек его треков (карточка во вкладке
  «Плейлисты» и шапка плейлиста): импортированные плейлисты без единой
  обложки больше не выглядят пустыми квадратами.
- Экран поиска: закреплённое поле при прокрутке, «Лучшее совпадение» в
  стеклянной карточке, на пустом экране — недавние запросы и лента карточек
  артистов с круглыми обложками.
- Встроенный резолвер-сервер: адрес включён в сборку по умолчанию — полные
  записи YouTube, недоступные напрямую, играют сразу после установки. В
  настройках («Резолвер-сервер») можно указать свой сервер или отключить
  источник.
- Онбординг при первом запуске: выбор языка из 20 языков интерфейса и экран про
  MicroG (что это, когда нужен, статус на устройстве, ссылка на официальный
  релиз). Пропускается одним нажатием, выбор сохраняется на устройстве.
- 20 языков интерфейса: en, ru, es, pt, fr, de, it, tr, pl, uk, ar, hi, bn, id,
  zh, ja, ko, vi, th, nl (включая RTL для арабского).
- Опциональный источник «Сервер»: само-хостинг резолвера полных аудиопотоков.
  Контракт и эталонная реализация — `docs/REMOTE_RESOLVER.md`; адрес сервера
  задаётся в настройках, без него источник неактивен.
- Диагностический инструмент `tool/youtube_client_probe.dart`: проверка каждого
  внутреннего клиента YouTube отдельно (манифест, битрейт, реальный GET-запрос).
- Релизная обвязка: LICENSE (MIT), CI (analyze + test), шаблон issue,
  CHANGELOG, adaptive-иконка, runtime-запрос `POST_NOTIFICATIONS`.

### Changed
- YouTube-записи из поиска играют всюду, где есть сервер: если CDN отвечает
  прямому запросу 403 (обычная история на мобильных сетях), приложение
  прозрачно перезапрашивает тот же трек через сервер-резолвер.
- Возрастные (18+) видео доступны и на сервере — с аккаунтными куками
  YouTube и решателем n-challenge (Deno); настройка описана в
  docs/REMOTE_RESOLVER.md.
- Выбор источников в поиске — теперь компактная кнопка-воронка с шитом
  (Все источники / Каталог / YouTube / SoundCloud / Сервер) вместо ряда
  чипов; Audius убран из поиска.
- Воспроизведение YouTube больше не привязано к одному внутреннему клиенту:
  резолвинг идёт по цепочке клиентов (`ios → tv → mweb → androidVr → safari →
  androidSdkless`) с реальной проверкой потока и запоминанием рабочего клиента.
  Ранее использовался только `androidSdkless`, который теперь на многих сетях
  зависает или получает HTTP 403.
- User-Agent запросов к CDN теперь всегда совпадает с клиентом, выпустившим
  ссылку (раньше всем ссылкам навязывался Android User-Agent — часть ссылок
  отбивалась ошибкой 403).
- Таймауты: жёсткий лимит 7 с на каждого клиента, общий бюджет резолва поднят
  до 20 с; запрос уведомлений Android 13+ выполняется при старте.

### Removed
- Мёртвый код (`glass_card.dart`), неиспользуемая web-платформа, зависимость
  androidx.multidex (не нужна при minSdk 21).

### Security
- `usesCleartextTraffic` выключен — весь трафик идёт по HTTPS.
- Данные приложения исключены из облачного бэкапа и переноса на новое
  устройство (библиотека сознательно живёт локально).
- Включены R8 + сжатие ресурсов для релизной сборки.
